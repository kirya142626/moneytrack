# MoneyTrack

Личный финансовый сервис: учёт доходов и расходов, бюджеты, цели накопления и аналитика.
Next.js 15 + TypeScript + Tailwind CSS, Supabase Auth/PostgreSQL для production и
локальная SQLite для запуска без внешних сервисов. Все возможности бесплатны.

Публикация на Vercel + Supabase с нуля описана в **[DEPLOY.md](DEPLOY.md)**.

## Возможности

- **Операции** — создание, редактирование и удаление доходов/расходов; поиск, фильтры,
  сортировка и постраничный вывод.
- **Категории** — 19 стандартных категорий, включая «Маркетплейсы» и «Игры»; собственные
  категории с иконкой и цветом без лимита.
- **Бюджеты** — лимиты на месяц по категории или общий бюджет, прогресс и состояния.
- **Цели накопления** — целевая сумма, срок, пополнения и расчёт нужного темпа.
- **Аналитика** — реальные графики Recharts: динамика, структура расходов, сравнение периодов,
  норма сбережений.
- **Настройки** — имя, валюта, тема, смена пароля, экспорт CSV и удаление аккаунта.
- **Бесплатный доступ** — все функции включены для каждого аккаунта: без подписки,
  тарифов, пробных периодов и платёжных данных.
- **Адаптивный интерфейс** — sidebar на десктопе, мобильная навигация, светлая/тёмная/песочная темы.

## Быстрый старт (локальный режим)

Локальный режим не требует Supabase, Docker и ключей. Данные хранятся в SQLite-файле.

```bash
npm install
npm run dev
```

Откройте <http://localhost:3000>, зарегистрируйтесь — аккаунт и 19 стандартных категорий
создаются автоматически.

- База по умолчанию: `data/moneytrack.db` (папка в `.gitignore`).
- Переопределить путь: `MONEYTRACK_DB_PATH=C:\path\to\moneytrack.db`.
- Существующим локальным аккаунтам категории «Маркетплейсы» и «Игры» добавляются
  автоматически при запуске приложения.
- Письма не отправляются: на странице восстановления пароля ссылка сброса показывается прямо
  в интерфейсе (только локальный режим).

## Переменные окружения

Скопируйте `.env.example` в `.env.local`:

```bash
cp .env.example .env.local
```

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | URL проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Публичный anon-ключ (защищён RLS) |
| `NEXT_PUBLIC_APP_URL` | Базовый URL для ссылок подтверждения почты и сброса пароля |
| `MONEYTRACK_DB_PATH` | Путь к SQLite-файлу в локальном режиме |

Если `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` заданы, приложение
автоматически переключается на Supabase. Иначе работает локальная SQLite.

На Vercel локальный режим запрещён: без переменных Supabase middleware возвращает
страницу **503 «MoneyTrack не настроен»**, а `backendMode()` выбрасывает понятную
ошибку. Это защищает от запуска production на эфемерной файловой системе.

`NEXT_PUBLIC_APP_URL` должен указывать на финальный адрес сайта. Если он не задан,
на Vercel используется системный `VERCEL_URL` текущего деплоя, а локально —
`http://localhost:3000`. После изменения `NEXT_PUBLIC_*` нужен Redeploy: значения
встраиваются в сборку.

Service role key и переменные платёжного провайдера не используются.

## Подключение Supabase

1. Создайте проект на <https://supabase.com>.
2. Выполните в **SQL Editor** по порядку: `supabase/migrations/0001_init.sql`,
   `0002_free_access.sql`, `0003_production_hardening.sql` (или `supabase db push`).
   Миграции создают таблицы, индексы, RLS-политики, триггер регистрации,
   стандартные категории и функцию удаления аккаунта. Подробности —
   в [`supabase/README.md`](supabase/README.md).
3. В **Authentication → URL Configuration** укажите:
   - Site URL: `http://localhost:3000` (или ваш production-домен);
   - Redirect URLs: `http://localhost:3000/auth/callback`, `http://localhost:3000/reset-password`,
     а также production-варианты.
4. Заполните `.env.local`:

   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
   NEXT_PUBLIC_APP_URL=http://localhost:3000
   ```

5. Перезапустите `npm run dev`. При регистрации Supabase отправит письмо подтверждения
   (если подтверждение включено в настройках Auth).

### Изоляция данных

- Все запросы Supabase выполняются от имени пользователя через SSR-клиент; RLS разрешает
  доступ только к строкам с `user_id = auth.uid()`.
- Таблицы подписок и платёжных данных отсутствуют. Приложение не выполняет запросов
  в обход RLS и не требует service role key.
- Пароли в локальном режиме хешируются scrypt с солью; сессии — случайный токен,
  в базе хранится только его SHA-256 хеш, cookie `HttpOnly`, `SameSite=Lax`.

## Публикация

Production рассчитан на **Vercel + Supabase**. Полная инструкция для новичка —
**[DEPLOY.md](DEPLOY.md)**: создание аккаунтов, миграции, ключи, Auth URL, почта,
домен и приёмочный чек-лист.

Коротко:

1. Создайте проект Supabase и выполните в SQL Editor `0001 → 0002 → 0003`.
2. Загрузите код в GitHub и импортируйте репозиторий в Vercel.
3. Добавьте в Vercel `NEXT_PUBLIC_SUPABASE_URL` и
   `NEXT_PUBLIC_SUPABASE_ANON_KEY`, затем задеплойте.
4. Пропишите домен Vercel в Supabase → Authentication → URL Configuration.
5. Добавьте `NEXT_PUBLIC_APP_URL` с финальным адресом и сделайте **Redeploy**.

Без Supabase на Vercel сайт вернёт 503 — локальная SQLite там не используется.

## Безопасность

- Секреты используются только на сервере; в клиент попадает лишь `NEXT_PUBLIC_*`.
  Service role key не требуется.
- Суммы хранятся в целых копейках, даты — в `YYYY-MM-DD`.
- Валидация входа выполняется и на клиенте, и в Server Actions.
- Все таблицы Supabase защищены RLS. Операции могут ссылаться только на категории
  своего пользователя, пополнения — только на свои цели; прямой вызов
  `seed_default_categories()` запрещён (миграция `0003`).
- Удаление аккаунта требует ввода подтверждения; в Supabase каскадно удаляет данные через
  `delete_own_account()`.
- CSV-экспорт доступен только авторизованному пользователю и возвращает только его операции.
- Добавлены security-заголовки (`X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, `Permissions-Policy`, HSTS на Vercel), `robots.txt`,
  `sitemap.xml` и PWA-манифест.
- На Vercel без Supabase приложение не запускается на локальной SQLite: middleware
  возвращает 503, а `backendMode()` выбрасывает ошибку.

## Ограничения и честные оговорки

- **Живой путь Supabase не проверен в этой среде**: нет аккаунта, ключей и Docker.
  Локальный режим полностью протестирован. Схема, RLS и Auth-пересылки написаны,
  но требуют прогонки на реальном проекте по чек-листу из [DEPLOY.md](DEPLOY.md).
- Локальная SQLite подходит для разработки и одного сервера. На serverless-платформах
  (Vercel) файловая система эфемерна — production обязан работать через Supabase.
- Письма в локальном режиме не отправляются — ссылка сброса показывается в UI.
  В production нужен SMTP: встроенный SMTP Supabase имеет жёсткие лимиты и подходит
  только для тестов.
- Бесплатный проект Supabase засыпает после недели без запросов; первый запрос после
  паузы может быть медленным.
